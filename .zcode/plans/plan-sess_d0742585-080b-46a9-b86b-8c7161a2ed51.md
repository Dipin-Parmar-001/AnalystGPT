# AnalystGPT Robustness Plan — Fixing Hallucination & Cross-Artifact Inconsistency (Hybrid Verification)

## 1. Evidence from run_20260906_090233 (verified)

All *data-derived* numbers were correct (churn rates, model metrics, confusion matrix recompute exactly from raw data / predictions.csv). Failures concentrate in **schema metadata + report prose**:

1. Raw column count stated as **30 / 33 / 44** across artifacts (correct: 33); engineered dataset as **50 vs 54** cols and **6 vs 10** features (correct: 50/6)
2. Report lists 4 **phantom columns** not in `feature_engineered_dataset.csv`; raw `CLTV` labeled as engineered
3. Report self-contradiction: "5,174 missing cells" vs "no missing values remained"; 11 imputed Total Charges omitted
4. Fabricated claims: "well-calibrated probabilities" (no calibration analysis exists), "r ≈ 0.5" (actual 0.787, no artifact reports 0.5)
5. `tuned_model_comparison.csv` labels parent row "XGBoost (parent)" while artifact is `logistic_regression_p0.pkl` — copied verbatim into `verified_metrics.json` ("ground truth") and `ml_summary.json`
6. Numeric verifier flagged '54' as unverified but **nothing acted**: wrong value stays in the report, banner rides along
7. `analyst_summary.json` is a byte-identical duplicate of task-3; task-1 narrative (source of the "30 columns" hallucination) never reconciled

## 2. Root causes in code

- **No authoritative dataset profile**: every agent re-derives shapes/columns from memory; memory compaction (`memory_manager.py:493-536`) evicts the stdout that held real numbers
- **Reporter precedence wrong**: report cites "(per analyst summary)" for schema facts — hallucinated narrative wins over correct `cleaning_summary.json`; no precedence rule exists
- **Validator is existence-only** (`artifact_validator.py`): no content checks, no cross-artifact reconciliation anywhere
- **`build_verified_metrics` provenance gaps** (`verification_script.py`): copies comparison-CSV labels verbatim (mislabel propagates), describes dataset as `cleaned_dataset.csv` while models trained on `feature_engineered_dataset.csv`, fixed metric priority can contradict ML agent's business selection
- **Silent failure paths**: empty `verified_metrics` silently disables verification (`orchestrate.py:463,857`); summary parse failures swallowed and replaced by **fabricated fallback summaries** with hardcoded defaults (`data_analyst_agent.py:631-703`, `ml_agent.py:600-746`); synthesis path skips structure validation (name mismatch `"ReporterAgent (Synthesis)"`, `artifact_validator.py:309`); orchestrator pre-writes `final_report.md` making the reporter's required-artifact check unfalsifiable
- **Prompt/code contradictions**: ML prompt forbids `best_model.pkl` (`prompts.py:1796`) while validator/orchestrator require it (`artifact_validator.py:369`, `orchestrate.py:534`); analyst `task.inputs` never injected (`data_analyst_agent.py:336-343`) though prompt mandates loading from it; tool budgets 7 (prompts) vs 10/13 (orchestrator)

**Decisions locked in**: severity-based failure policy; **hybrid verification** (deterministic gates first, LLM consistency judge as the final narrative-acceptance pass); implement all phases; stay within current 4-agent architecture (files as handoff).

## 3. Implementation

### Phase 1 — Dataset Profile Contract (kills the 30/33/44, 50/54, 6/10 class)
New `agents/run_context.py`:
- `build_dataset_profile(run_dir, stage)` — deterministic, from the on-disk CSV only: rows, cols, exact column list with dtypes, per-column missing counts, and a diff vs the previous stage (engineered features = columns added by feature engineering). Writes `dataset_profile_<stage>.json` (raw / cleaned / featured) with source-file hash + mtime.
- Orchestrator (`orchestrate.py`) calls it after every data-touching task; profile JSON injected verbatim into all subsequent agent prompts as `AUTHORITATIVE DATASET PROFILE — quote schema facts from here; never recompute or state shapes/column counts from memory`.
- Reporter prompt: shapes/columns/feature lists may come **only** from the profile; "per analyst summary" schema citations banned.

### Phase 2 — Deterministic cross-artifact consistency checker
New `agents/consistency_checker.py` → `validate_cross_artifact_consistency(run_dir) -> ConsistencyReport`, invoked by the orchestrator after every task and before the reporter; findings persisted to `consistency_report.json` with per-finding `severity` (critical/minor), `artifacts_involved`, `claim`, `expected`, `actual`:
- **Schema contract**: every `*_shape`/column-count claim in summary JSONs vs profile + actual CSV headers (no tolerance); claimed engineered features ⊆ actual columns; listed columns exist; no column classified into two categories; column-class counts sum to total
- **Data reconciliation**: `missing_values_handled` claims vs computed NaN counts in output CSVs; imputation claims vs NaN before/after; stale-caveat detection (claims about NaNs that no longer hold)
- **Lineage/label reconciliation**: label + param strings in `tuned_model_comparison.csv` must match the `model_registry.json` entry of the artifact referenced in the same row (catches XGBoost/LR bug); champion consistent across `champion_model.json` / `model_registry.json` / `ml_summary.json` / best-by-primary-metric from `model_comparison.csv`; `improved` flags vs recomputed deltas; parent artifact exists
- **Narrative-claim lexicon**: model names, encoding methods, feature names in summaries must appear in registry/profile/CSVs
- Wire findings into the existing combined validation/retry loop (`orchestrate.py:656-813`) as first-class validation errors so retries receive the specific contradictions

### Phase 3 — Make deterministic verification a gate that acts
`numeric_verifier.py` + `reporter_agent.py` + `orchestrate.py`:
- **Section-aware numeric binding** replacing pool-membership: markdown tables in the report must be copied row-for-row from `verified_metrics.models` (verifier compares parsed tables cell-by-cell by model name); inline per-segment claims must match the matching segment in `verified_metrics`; derived-number support (value computed from two verified numbers) recognized instead of flagged
- **Narrative claim rules**: "well-calibrated"/calibration claims require calibration metrics to exist; correlation values must match `correlation_matrix.csv` within tolerance; model names must exist in registry. Unsupported claims auto-replaced with "not verified in current run" deterministically *before* the banner path
- **Act on findings**: pass the unverified-claim list into the orchestrator retry prompt (already collected at `orchestrate.py:675-683`); re-enable correction loop (`max_correction_turns>0` in synthesis path)
- **Close silent paths**: empty `verified_metrics` → run marked `unverified`/error, never silent success; fix synthesis agent-name mismatch; stop pre-writing `final_report.md` before validation (validate returned markdown, persist after)
- **`build_verified_metrics` provenance fixes**: resolve model labels from `model_registry.json` instead of copying comparison rows; record `dataset_source` for model metrics separately from dataset-stats source; expose champion-selection rule used

### Phase 4 — LLM Consistency Judge (hybrid layer, core phase)
New `agents/consistency_judge.py`; new `JUDGE_PROMPT` in `prompts.py`. Runs **after** the deterministic gates pass, once per report:
- **Input** (roles labeled): final report, a compact projection of `verified_metrics`, the deterministic `consistency_report.json` findings (so the judge complements, not duplicates), dataset profile summary
- **Output contract**: JSON findings `[{severity: critical|minor, quote, issue, evidence_ref, suggestion}]`, max 15; parsed via `fallback_parser.py`; on invalid JSON → one retry → fail-open to deterministic-only results (logged, never blocks on judge malfunction)
- **Judge prompt rules**: flag only claims unsupported by ground truth, semantic contradictions between sections, overstatements, and causal claims without evidence; every finding MUST quote exact report text and name the contradicting metric/artifact; do NOT rewrite the report; do not flag style
- **Anti-judge-hallucination guards** (deterministic post-validation of judge output): finding dropped unless (a) `quote` exists verbatim in the report (whitespace-normalized), (b) `evidence_ref` resolves to a key in verified_metrics/consistency findings; severity enforced by code, not by the judge
- **Handling of findings**: critical → exactly **one** targeted revision pass (reporter receives findings, revises; deterministic numeric verification + consistency checker re-run on the revision so numbers can't drift); still critical → severity policy applies. Minor → appended to Operational Caveats as annotations
- **Cost/config bounds**: temperature 0.1; default 1 judge call (+1 revision, +1 bounded judge re-check after revision = worst case 3); `JUDGE_MODEL` env override (a stronger model than worker agents recommended if available); judge can be disabled via config → pipeline degrades gracefully to deterministic-only
- Judge results stored under `llm_judge` in `consistency_report.json` with provenance

### Phase 5 — Prompt & contract hardening
`prompts.py`, `data_analyst_agent.py`, `ml_agent.py`, `orchestrate.py`, `artifact_validator.py`:
- **Resolve `best_model.pkl` contradiction**: orchestrator writes it deterministically as a copy of the champion artifact after model_comparison validates; agents never create it; validator/orchestrator requirements satisfied by construction
- **Honest fallback summaries**: remove fabricated defaults (encoding method, `target_column: "target"`, identifier lists, first-row-as-best); emit minimal summary with `status: "incomplete"`, empty schema fields, explicit caveat; checker/judge/reporter treat them as untrusted context
- **Reporter precedence hierarchy** in prompt: dataset profile / verified_metrics > structured JSON artifacts > narrative summaries; every data claim must name its artifact
- Inject `task.inputs` into analyst task blocks; align tool budgets (prompts' 7 vs orchestrator 10/13); make planner schema example dataset-agnostic (remove churn/`customerID` priming); persist plan to `plan.json` and surface planner `notes` in the UI

### Phase 6 — Severity policy, status semantics, observability
`orchestrate.py`, `main.py`:
- Run status: `completed` / `completed_with_warnings` / `failed_consistency` — determined by severity-weighted findings (deterministic + judge) after retries/revision exhaust
- **Severity policy**: critical findings surviving retries + revision → run fails consistency; report withheld as "final" and findings surfaced in UI; minor → report delivered with prominent annotations. Thresholds in config
- Machine-readable findings list returned to Streamlit ("Consistency Findings" section); per-task manifest (task, agent, artifacts, validation results, retries) written to run dir for auditability and plan-vs-output drift checks

### Phase 7 — Eval harness + tests
- `evals/run_consistency_eval.py`: replays the golden scenario (test.txt query + Telco upload) and asserts: 0 critical findings, every report numeric verified, schema facts == profile, report tables == verified_metrics; runs with judge enabled and disabled
- Unit tests (pytest) for consistency checker + numeric verifier using **synthetic run dirs**; `outputs/run_20260906_090233` as regression fixture that must produce the exact 7 issue classes from §1
- Judge tests with mocked LLM: quote/evidence validation guards, fail-open behavior, revision-loop bounds
- Run-unit tests: severity policy transitions, empty-verified-metrics handling, fallback-summary honesty

## 5. Acceptance criteria
1. Replaying the test.txt golden run: zero contradictory schema facts; report tables match `verified_metrics` exactly; no unsupported narrative claims; schema facts equal the profile
2. The 7 issue classes from §1 are each mechanically caught on the fixture run (asserted in tests)
3. Every judge finding is quote-verified and evidence-backed; judge failure/disabling never blocks the pipeline (graceful deterministic-only degradation)
4. Critical unresolved findings produce `failed_consistency` status, never a silently flawed report
5. Added LLM cost bounded: worst case 3 judge calls per run; deterministic checks add no LLM calls
